# Lively AI 도우미 설치 & 사용 가이드 (비개발자용)

이 가이드대로 하면 새 노트북에서 **조직 전용 AI 도우미(Claude Code)**를 쓸 수 있습니다.
조직 맥락(우리 일하는 방식·도메인·프로젝트)을 이미 아는 상태로 켜집니다.

> 어려운 거 없습니다. **명령 한 줄(또는 스크립트 한 번) 실행 → 끝.** 5~10분 걸려요.
> git clone·레포 주소 같은 건 필요 없습니다 — 게이트웨이에서 설치 묶음을 바로 받아옵니다.

---

## 1. 설치 (한 번만)

관리자에게 **설치 명령 한 줄**(본인 토큰이 박힌)을 받는 게 가장 쉽습니다. 관리 페이지 `[설치]` 탭에서 본인 토큰을 발급하면 그 한 줄이 그대로 나옵니다.

설치는 **한 줄**입니다. 명령에는 **토큰이 들어가지 않습니다** — 설치 도중 터미널이 물어보고, 입력해도 화면에 보이지 않습니다(셸 기록에도 안 남습니다).

### Mac / Linux

터미널에 붙여넣고 엔터:

```
curl -fsSL <게이트웨이>/cli | sh
```

### Windows

시작 메뉴에서 **PowerShell** 을 열고 붙여넣고 엔터:

```
irm <게이트웨이>/cli.ps1 | iex
```

### 그 다음 (Mac·Windows 동일)

1. **"접속 토큰을 붙여넣으세요"** → 관리자가 준(또는 `[내 AI 세션 생성]` 화면에서 본인이 발급한) 토큰을 붙여넣고 엔터.
   입력해도 **화면에 아무것도 안 보이는 게 정상**입니다(비밀번호처럼 가려집니다).
2. Claude Code 가 없으면 **"지금 설치할까요?"** → `Y` 엔터.
3. 회사 계정 **로그인 브라우저 창**이 뜨면 로그인.
4. **`=== 끝! ===`** 이 보이면 완료. 확인은 `lively status`.

> 다시 실행해도 안전합니다(멱등) — 이미 설치돼 있으면 최신으로 맞추기만 합니다.
> 설치가 끝나면 터미널에서 **`lively`** 명령을 쓸 수 있습니다(`lively status` · `lively doctor` · `lively update` · `lively run <프로젝트번호>`).

---

## 2. 켜기

1. **아무 폴더**(자기 코드 레포 포함)에서 `claude` 를 켜면 됩니다 — user-level 설치라 실행 위치는 상관없습니다(Windows·Mac 동일).
   - Windows: 폴더 주소창에 `powershell` 치고 엔터 → 까만 창에 `claude` 엔터.
   - Mac: 터미널에서 `claude`.
2. 처음이면 **브라우저 로그인 창**이 떠요 → **회사 계정으로 로그인**.
3. "이 폴더를 신뢰하시겠습니까(trust)" 류 확인이 뜨면 **승인**(회사 배포 설정이라 안전). → 끝.

이제 대화하면 됩니다. (훅 특성상 **다음 세션부터** 시작 현황 주입·리플렉스가 적용됩니다.)

> 세션 시작 시 팀 현황(검토 대기 건수 등)이 자동으로 뜹니다 — **Mac·Windows 모두 동작**합니다.

---

## 3. 예전에 쓰던 AI 환경 가져오기 (해당되는 분만)

전에도 이 컴퓨터에서 AI(클로드 코드 등)로 일해 오셨다면 **그때 쌓인 것들이 있습니다** — AI가 기억해 둔 작업 메모, 직접 만든 스킬, 연결해 둔 외부 서비스, 쓰던 코드 저장소.

`claude` 를 켜고 이렇게 물어보세요:

> **온보딩 도와줘**

그러면 도우미가 ① 지금 컴퓨터에 뭐가 있는지 **읽기만 해서** 보여주고, ② 항목마다 어디로 보낼지 **하나씩 같이 정하고**, ③ 정하신 것만 실행합니다.

**원본은 건드리지 않습니다.** 복사만 하고, 지우거나 덮어쓰지 않습니다.

### "예전 기억이 사라졌어요"

사라지지 않았습니다. AI의 작업 메모는 **폴더마다 따로** 저장돼서, 다른 폴더에서 켜면 안 보일 뿐입니다. 위 도우미가 다른 폴더에 있던 것까지 찾아서 보여줍니다.

### 회사 위키로 올리면 뭐가 좋나요?

내 컴퓨터의 메모는 **그 폴더에서 켠 나만** 볼 수 있습니다. 회사 위키에 올리면 **내가 다른 폴더에서 일할 때도, 동료가 일할 때도** AI가 그걸 참고합니다. 그래서 "이건 나중에 남이 알아도 좋겠다" 싶은 건 위키로 올리시길 권합니다.

반대로 **개인적인 건 그냥 두세요.** 도우미가 전부 올리지 않고 하나씩 물어봅니다.

> 라이블리 웹의 **터미널** 탭에서 쓰고 계시다면 이 절은 건너뛰셔도 됩니다 — 그 세션은 회사 서버에서 돌아서 가져올 예전 환경이 없습니다.

---

## 4. 어떻게 쓰나요?

그냥 **한국어로 물어보면** 됩니다. 예시:

- "우리 커머스 도메인에 어떤 데이터가 있는지 알려줘"
- "이번 분기 진행 중인 프로젝트 목록 정리해줘"
- "brands 테이블에서 채널 타입별 브랜드 수 세줘"
- "결제 관련 도메인 부채 뭐가 있어?"

도우미가 회사 맥락(도메인 맵)과 실제 데이터를 직접 조회해서 답합니다.
끝낼 때는 까만 창에 `exit` 치거나 창을 닫으면 됩니다.

## 5. 최신 내용으로 업데이트 — **할 일 없습니다(자동)**

회사 맥락(일하는 방식·도메인 설명 등)은 원래도 **매 세션 자동 갱신**이고,
훅·설정 같은 **키트 자체도 이제 자동으로 업데이트**됩니다.

Claude Code(또는 Codex)를 켜면 라이블리가 최신인지 확인하고, 다르면 **백그라운드로 받아 설치**합니다.
지금 하던 세션은 방해하지 않고, **다음에 켤 때부터** 새 훅·설정이 적용됩니다.
(업데이트가 끝나면 다음 세션 첫머리에 "키트가 자동으로 업데이트됐습니다" 한 줄이 뜹니다.)

**끄고 싶다면**: 환경변수 `LIVELY_NO_AUTO_UPDATE=1` (조직 전체는 관리자가 관리탭에서 토글).

**지금 당장 맞춰야 할 때만** (Mac·Windows 동일):

```
lively update
```

> ⚠ 한 가지 예외 — 관리자가 **새 MCP 서버를 추가**했을 땐 Claude Code 쪽 등록(`claude mcp add`)만은
> 자동으로 되지 않습니다(백그라운드에서 등록을 지웠다 다시 넣다가 실패하면 MCP 연결이 사라질 수 있어 일부러 뺐습니다).
> 그때 `lively update` 를 한 번 돌리면 됩니다 — **CLI 는 앞에서 지켜보고 있으니 안전하게 할 수 있습니다.** (Codex 는 자동입니다.)

## 6. 제대로 붙었는지 확인하기 (AI에게 점검시키기)

`lively doctor` 는 **내 컴퓨터 쪽 설치 상태**(설치됐나·등록됐나·최신인가)를 봅니다. 그런데 정말 궁금한 건 보통 그 다음입니다 — **회사 서버의 최신 설정이 지금 이 AI에게 그대로 들어와 있나?** 회사가 새로 배포한 스킬이 이 AI에게 실제로 붙었는지, 회사 맥락이 이번 대화에 주입됐는지는 **AI 자신만 알 수 있어서**, 물어보는 게 가장 정확합니다.

**언제 쓰나** — 설치 직후 · 회사가 새 스킬이나 규칙을 배포했다고 들었을 때 · AI가 회사 사정을 모르는 것 같을 때 · 웹이나 앱에 MCP만 연결해 두고 잘 붙었는지 볼 때.

아래를 **통째로 복사해 AI에게 붙여넣으세요.** 내용이 무슨 뜻인지는 몰라도 됩니다 — 몇 초 뒤 표 한 장으로 답합니다.

```
라이블리 배선 점검. 진단만 하고 아무것도 고치지 마라. 스킬을 실행하거나 스킬·지식 본문을 열지 마라(토큰 낭비).

1) whoami 를 호출한다. 실패하면 "MCP 미연결"만 보고하고 끝낸다.
2) 셸을 쓸 수 있으면 아래 --- 사이를 그대로 한 번 실행한다. 못 쓰면 이 단계는 "확인불가".
--- 여기부터
GW=${LIVELY_GATEWAY_URL:-$(cat ~/.lively/gateway-url 2>/dev/null)}; TOK=${LIVELY_TOKEN:-$(cat ~/.lively/token 2>/dev/null)}
M=~/.lively/managed-harness-assets.json; A(){ curl -fsS -m 10 -H "Authorization: Bearer $TOK" "$GW$1"; }
LV=$(command -v lively || echo ~/.lively/bin/lively)
{ [ -n "$GW" ] && [ -n "$TOK" ] && command -v jq >/dev/null; } || { echo "게이트웨이·토큰·jq 중 없는 것 있음 → MCP 전용 환경으로 판정"; exit 0; }
echo "[설치] $("$LV" doctor --json 2>/dev/null | jq -r '[.checks[]|select(.pass==false)|"\(.name)(\(.detail))"]|if length==0 then "이상 없음" else join(" · ") end' || echo "lively CLI 없음")"
H=$(jq -r 'keys[0]//"claude"' $M 2>/dev/null)
A "/api/ui/org/runner/assets?harness=$H" | jq -r '.assets[]|"\(.id)\t\(.kind)\t\(.content_hash)"' | sort > /tmp/lv-s
jq -r --arg h "$H" '.[$h]|to_entries[]|"\(.key)\t\(.value.kind)\t\(.value.hash)"' $M 2>/dev/null | sort > /tmp/lv-l
echo "[자산] $H · 서버 $(wc -l </tmp/lv-s|tr -d ' ')개 / 로컬 $(wc -l </tmp/lv-l|tr -d ' ')개$(cmp -s /tmp/lv-s /tmp/lv-l && echo ' · 해시까지 동일')"
diff /tmp/lv-s /tmp/lv-l | grep '^[<>]' | cut -f1,2 | sed 's/^/  불일치 /'
jq -r --arg h "$H" '.[$h][].file' $M 2>/dev/null | while read -r f; do [ -f "$f" ] || echo "  파일없음 $f"; done
awk -F'\t' '{printf "%s:%s ",$2,$1}' /tmp/lv-s | fold -s -w 160 | sed 's/^/  /'; echo
printf '[훅] 서버 '; for E in SessionStart UserPromptSubmit PreToolUse PostToolUse Stop SubagentStop Notification PreCompact PostCompact SessionEnd; do
  N=$(A "/api/ui/org/runner/hooks?harness=$H&event=$E" | jq '.hooks|length' 2>/dev/null); [ "${N:-0}" = 0 ] || printf '%s=%s ' "$E" "$N"; done
echo "· 러너 마지막 발화 $(ls -t ~/.lively/custom-hooks-*.json 2>/dev/null|head -1|xargs jq -r .at 2>/dev/null|awk -v n=$(date +%s) '{printf "%d초 전",(n*1000-$1)/1000}')"
A /api/ui/org/preview | jq -r .context > /tmp/lv-c
echo "[맥락] $(awk '/^## /{h=$0;o[++n]=h;next} /^- /{if(h)c[h]++} END{for(i=1;i<=n;i++)printf "%s(%d) ",substr(o[i],4),c[o[i]]+0}' /tmp/lv-c)"
[ "$(tr -d '[:space:]' </tmp/lv-c|shasum)" = "$(tr -d '[:space:]' <~/.lively/context.md 2>/dev/null|shasum)" ] && echo "  이 세션이 받은 것 = 서버 최신" || echo "  주의: 서버가 세션 시작 뒤 변경됨 — 다음 세션에 반영"
echo "[MCP] 이 토큰에 열린 툴 $(curl -fsS -m 10 -X POST "$GW/mcp" -H "Authorization: Bearer $TOK" -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'|sed -n 's/^data: //p'|jq '.result.tools|length')개"
--- 여기까지
3) 추가 호출 없이 지금 이 세션만 보고 대조한다.
   - 2)의 [자산] 목록에 있는 스킬·서브에이전트가 내가 실제로 쓸 수 있는 목록에 다 있나 → 빠진 것만 적는다.
   - 2)의 [맥락] 섹션·항목 수가 이 세션 첫머리에 주입된 회사 맥락과 맞나.
4) knowledge_search 를 q="라이블리" mode="names" limit=3 으로 한 번 호출한다.

보고는 7행 표 하나만: MCP 연결 / 신원·모드 / 설치 상태 / 스킬·서브에이전트 / 맥락 주입 / 훅 / 검색 동작.
각 행은 OK·문제·확인불가 중 하나 + 근거 한 줄(수치). 문제인 행만 조치 한 줄. 그 외 설명 금지.
```

- **어디서든 됩니다** — 내 컴퓨터의 `claude`·`codex`, 라이블리 웹의 [내 AI 세션], MCP만 연결한 다른 AI 웹·앱. 그 환경에서 볼 수 없는 항목은 AI가 `확인불가`로 적습니다(고장이 아닙니다).
- **읽기만 합니다** — 아무것도 고치거나 지우지 않고, 토큰도 거의 쓰지 않습니다(스킬 본문을 열지 않도록 막아 두었습니다).
- 표에 `문제` 가 있으면 그 줄의 조치를 따르고, 그래도 안 되면 **표를 그대로** 관리자에게 보내세요.

## 7. 잘 안 될 때

**먼저 이걸 돌려보세요** — 무엇이 잘못됐고 어떻게 고치는지 알려 줍니다:

```
lively doctor
```

| 증상 | 해결 |
|---|---|
| `lively` 쳤는데 "명령을 찾을 수 없음" | 터미널을 **새로 열고** 다시(설치 직후엔 현재 창의 PATH 에 아직 없습니다). 그래도 없으면 설치 한 줄(`curl -fsSL <게이트웨이>/cli \| sh`)을 다시 실행. |
| `claude` 쳤는데 "명령을 찾을 수 없음" | 위와 같습니다 — 창을 새로 열어 보고, 그래도 안 되면 `lively install`. |
| 설치 중 "토큰이 거부됐습니다" | 관리자가 발급한 본인 토큰이 맞는지 확인(`[내 AI 세션 생성]` 화면에서 본인이 발급 가능). 다시 넣으려면 `lively login`. |
| 설치 중 "게이트웨이 응답 없음" | 주소·네트워크·VPN 확인. `lively doctor` 가 어디서 막혔는지 짚어 줍니다. |
| 도메인/DB 질문에 "연결 안 됨" | MCP 미연결 — `lively doctor` 로 확인하고 `lively update`. |
| 로그인이 안 됨 | 회사 계정인지 확인. 그래도 안 되면 관리자 문의. |

막히면 `lively doctor` 출력을 캡처해서 조직 관리자에게 보내주세요.

## 8. 제거하기

Lively 설정을 머신에서 **완전히 떼어내고 싶을 때**(이직·정리 등). Mac·Windows 동일:

```
lively uninstall            # 미리보기 → 확인 후 제거
lively uninstall --dry-run  # 무엇이 지워질지만 보기(아무것도 안 지움)
```

동작:
- 무엇이 지워질지 먼저 **미리보기**를 보여주고, **정말 지울지 한 번 물어봅니다**(y 눌러야 진행).
- 떼어내는 것: `claude`/`codex` 의 lively 훅(커스텀 훅 런너 포함)·MCP 등록(게이트웨이 + 조직이 추가한 MCP 서버) · 자동승인(auto-approve) 설정 · 셸 토큰 설정 · `~/.lively` 폴더.
- **건드리지 않는 것**: 여러분의 다른 설정(tmux 알림·codex 로그인/모델·셸 별칭 등)은 그대로 둡니다.
- `~/.lively` 는 바로 영구삭제가 아니라 **`~/.lively.removed-<날짜>` 로 옮겨**둡니다(되돌릴 수 있음 — 안에 설치 전 원본 백업도 함께 보관). 완전 정리 전까지는 두세요.

옵션(Mac uninstall-mac.sh): `--dry-run`(미리보기만) · `--purge`(완전 삭제) · `--harness claude|codex`(한 하네스만) · `--yes`(확인 생략).

> **임시로 조용히/격리하고 싶을 뿐**이라면 제거하지 말고 **실행 모드**를 쓰세요(설치는 그대로): 그 세션만 `lively run --readonly`(읽되 라이블리에 안 씀) 또는 `lively run --incognito`(라이블리 전혀 안 씀·클린룸), 디폴트는 `lively mode <normal|readonly|incognito>`. 훅만 잠깐 끄려면 `LIVELY_OFF=1`. 제거(uninstall)는 영구적입니다.
> 토큰 회수는 관리자 몫입니다 — 이직 시엔 관리자에게도 알려 서버에서 접속 권한을 끊어달라고 하세요([온보딩.md](온보딩.md) 오프보딩).

### (관리자용 메모)
멤버 설치는 git clone 이 아니라 게이트웨이 **`/install` 토큰게이트 번들**로 단일화돼 있습니다(관리 UI `[설치]`/`[구성원 추가]` 탭이 토큰 박힌 한 줄 명령을 발급). 스크립트로 줄 경우 `setup-windows.ps1` 은 다음만 필요합니다:
- `McpUrl` — MCP 게이트웨이 주소(예: `http://<host>:8080/mcp`). 파라미터 또는 `LIVELY_GATEWAY` 환경변수. 설치 번들도 여기서 받습니다(`.../install`).
- `McpToken` — 사용자별 토큰(비우면 실행 중 입력). 사람마다 다른 토큰 권장.
- `McpLabel` — MCP 등록 라벨(기본 `lively`). 단일 출처는 `lively/scripts/register-clients.sh` — 변경은 거기 먼저.

게이트웨이(`lively`)는 사내망에서 reachable 해야 하고, 클라이언트가 외부면 노출/터널 필요. 멤버 추가·신원(이메일·Discord·ClickUp 연결)은 관리 UI `[구성원]` 탭에서 — 상세는 [온보딩.md](온보딩.md).
