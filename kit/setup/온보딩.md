# 새 멤버 온보딩 가이드

> 단일 출처: `workflow-std/setup/온보딩.md` (발행 시 `/install` 번들에 포함 → 설치 시 멤버 머신으로).
> 멤버용 사용법은 [사용가이드.md](사용가이드.md), 훅 상세는 `context-ontology/runbooks/hooks.md`.

온보딩은 **세 층**입니다 — 섞어서 생각하면 빠뜨립니다.

| 층 | 언제 | 누가 | 어디서 |
|---|---|---|---|
| **① 조직 셋업** | 인스턴스당 1회 | 관리자 | 웹 **`#/onboarding`** — 5단계 진행률(회사·페르소나·업무규칙 / 카테고리 / 지식 / 구성원 / 제품 DB). 다 채우면 AI 세션의 셋업 안내가 **자동으로 사라집니다**. |
| **② 멤버 추가** | 멤버당 1회 | 관리자 | 아래 **§A** (~5분) |
| **③ 멤버 설치 + 내 환경 가져오기** | 멤버당 1회 | 멤버 본인 | [사용가이드.md](사용가이드.md) — 설치 1커맨드(~5분). 예전에 AI를 쓰던 사람이면 `온보딩 도와줘` 로 **기존 작업 메모리·스킬·연결 이관**(사용가이드 §3) |

**흔한 실수: ②③만 하고 ①을 잊는 것.** 그러면 멤버가 설치를 마쳐도 회사 맥락이 비어 있어 AI 가 baseline 안내만 합니다. ①의 진행상황은 웹 `#/onboarding` 에 있고 **AI 세션에도 같은 내용이 주입**되므로, 세션에서 "온보딩 어디까지 됐어?"라고 물어도 됩니다.

> **전달 방식(2026-06-12~):** 컨텍스트·리플렉스는 **user-level 훅**으로 전달됩니다. 한 번 setup 하면 멤버는 **어느 폴더에서 `claude` 를 켜든**(자기 코드 레포 포함) 회사 맥락+리플렉스를 받습니다 — 실행 디렉토리 무의미. (`/install` 번들을 푼 폴더는 설치 부트스트랩 아티팩트이지 "여기서만 켜야 하는 워크스페이스"가 아닙니다.)

## A. 관리자 절차 (멤버당 1회)

조직콘텐츠·멤버·신원은 모두 **게이트웨이 DB 가 단일 진실원천**이고 관리 웹 UI(`/ui`)에서 편집한다.
(구 `lively-org`(조직콘텐츠 git)·`context-setup`(발행물 git) 레포 + `build-context.mjs --publish` 발행 단계는 폐기됐다 — 2026-06-24. 콘텐츠는 위키 DB 에서 `/install` 이 동적 생성하고, 설치는 그 번들 한 경로로 단일화. 엔진 `workflow-std` + 게이트웨이 `context-ontology` 만 유지.)

1. **멤버 추가** — 관리 UI `/ui` '구성원' 탭에서 멤버 생성. 채울 것(저장 시 person/person_identity 로 자동 동기화 → 비개발자 UI 편집이 즉시 신원 매칭에 반영):
   - 표시명 + **이메일** (필수 — Slack/Notion/ClickUp 교차소스 신원 조인 키)
   - 외부계정 연결: **Discord id**(봇 API 가 이메일을 안 주므로 수동 바인딩 필수), **ClickUp 이메일**(초대 주소와 동일해야 자동 조인)
   - **권한(scope)**: 전체 7종 `items·context·db·admin·runtime·memory·code`(단일출처 `context-ontology/src/capabilities/scopes.ts`). 보통 멤버는 `items·context·db`.
2. **토큰 발급** — 같은 관리 UI '구성원/토큰' 탭에서 그 멤버 토큰 발급(회수 가능한 **DB 토큰**, revoke 즉시·재시작 불요).
   발급하면 **토큰이 박힌 `/install` 설치 명령 한 줄**(OS별)이 그대로 나온다 — 멤버에게 그것만 전달하면 된다.
   - ※ `admin`(데이터/정책)·`runtime`(커스텀 훅·AI 도구)은 **반드시 DB 토큰** — 정적 토큰(`.env` `AUTH_TOKENS_JSON`) 불가(회수 불가 토큰의 fleet 제어 차단 = kill-switch).
   - 부트스트랩/CI 등 예외에만 `.env` `AUTH_TOKENS_JSON` 정적 토큰(`openssl rand -hex 32`, 추가 시 게이트웨이 재시작). 채팅에 평문으로 남기지 말 것.
3. **ClickUp 멤버 초대** — 1번과 같은 이메일로. (Discord 는 봇이 이미 서버에 있어 추가 작업 없음.)
4. 토큰(또는 발급된 설치 명령)을 멤버에게 **안전한 채널로** 전달 (1Password/대면 등 — 메신저 평문 금지).

## A2. 오프보딩 (멤버 이탈·정리 — install 의 역연산)

멤버가 나가거나 머신을 정리할 때. **클라이언트 제거(멤버 머신) + 서버측 권한 회수(게이트웨이)** 두 쪽을 모두 해야 한다.
이건 **영구 제거**다 — 일시 비활성(incognito `LIVELY_OFF=1`, §D)과 다르다.

1. **클라이언트 제거(멤버 머신)** — 멤버가 [사용가이드.md §7](사용가이드.md) 대로 `bash setup/uninstall-mac.sh` 실행.
   `~/.claude/settings.json` 의 lively 훅 + `claude mcp remove lively`, `~/.codex/config.toml` 의 lively-managed 블록,
   `~/.zshrc` 의 `LIVELY_TOKEN` export, `~/.lively/` 자산을 떼어낸다(tmux 등 사용자 설정은 보존, 백업 먼저).
   머신 회수라 멤버가 못 하면 관리자가 그 계정에서 실행하면 된다.
2. **서버측 권한 회수(게이트웨이 — 필수)** — 관리 UI `/ui` '구성원/토큰' 탭에서 **그 멤버 토큰을 회수(revoke)** — DB 토큰은 즉시 무효(재시작 불요). (정적 `.env` `AUTH_TOKENS_JSON` 토큰이었다면 그 항목 삭제 + 게이트웨이 재시작.)
   클라이언트 제거만으로는 토큰이 살아있어 그 토큰을 아는 사람이 계속 접속 가능하다. 서버에서 끊어야 진짜 차단된다.
3. **토큰 로테이션 트리거(보안)** — 유출 의심/공용 머신이었다면 그 멤버 토큰뿐 아니라 같은 채널로 노출됐을 수 있는
   토큰도 함께 로테이션(§E "토큰을 잃어버림/유출 의심" 절차). 최소한 이탈 멤버 토큰은 재발급하지 말고 **영구 폐기**.
4. (선택) 신원 정리 — 사람을 완전히 지우려면 `context-ontology` 에서 해당 person/person_identity 비활성화.
   보통은 과거 작업 귀속(audit)을 위해 person 은 남기고 토큰만 회수한다.

> 제거 안전장치: uninstall 은 **lively-managed 영역(센티넬/식별 가능 훅)만** 떼고, 마커가 없으면 그 파일은 안 건드린다.
> `~/.lively` 는 기본 휴지통 이동(`~/.lively.removed-<타임스탬프>`)이라 되돌릴 수 있고, `--purge` 로 완전 삭제한다.
> 무엇이 지워질지 먼저 보려면 `--dry-run`.

## B. 멤버에게 전달

멤버 설치·사용·트러블슈팅 절차는 **[사용가이드.md](사용가이드.md)** 에 있습니다(토큰 박힌 `/install` 한 줄 명령 붙여넣기 — Mac/Windows 동일, 또는 setup 스크립트 실행). 멤버에게는 그 문서 + 2단계에서 발급한 토큰(또는 설치 명령)만 전달하면 됩니다.

관리자가 멤버에게 **미리 일러줄 것** 두 가지:
- 첫 `claude` 실행 시 **신뢰(trust) 프롬프트** 1회 승인 (훅 실행 동의 — 회사 배포라 안전).
- **세션 훅(시작 현황 주입·라이트백 게이트)은 Mac·Windows 모두** 동작(2026-06-17 정정 — 이전 "Windows 미지원"은 오정보).

## C. 플랫폼별 지원 범위 — **Mac/Windows 동일**

| | Mac | Windows |
|---|---|---|
| 팀 컨텍스트 자동 전달(user-level 훅 + 정적 파일) | ✅ | ✅ |
| MCP 게이트웨이 툴(스토어·도메인맵·ClickUp·DB·메모리) | ✅ | ✅ |
| **세션 훅**(시작 현황 주입·라이트백 게이트·자가 게이팅·커스텀 훅) | ✅ | ✅ |

**구 "Windows 훅 미지원"은 오정보였음(2026-06-17 정정).** Claude Code 는 Windows 에서 훅을 정상 실행하고
(공식 docs), 우리 설치기는 Windows 용으로 절대경로 forward-slash 커맨드를 생성해 셸 의존이 없다. 단
`setup-windows.ps1` 이 `~/.lively` 를 `$env:USERPROFILE`(=Node `os.homedir()`) 기준으로 써야 훅이 읽는다(06-17 수정).
상세: `context-ontology/runbooks/hooks.md` §8.

## D. 전달 메커니즘 (user-level)

- **컨텍스트**: setup 이 `~/.lively/context.md`(정적 org-content) 를 깔고, SessionStart 훅(`session-preload`)이 그걸 + 게이트웨이 라이브 현황을 주입. 정적 컨텍스트 갱신은 **설치/업데이트 재실행**(`/install` 최신 묶음 — Mac `[설치]` 탭 업데이트 명령 / Windows `update-windows.ps1`), 라이브 현황은 세션마다 자동.
- **자가 게이팅(work-roots)**: writeback 게이트는 'lively work' 세션에서만 작동 — **cwd 가 `~/.lively/work-roots`(줄당 절대경로 prefix; env `LIVELY_WORK_ROOTS` 로도 augment) 아래** OR **그 세션에서 lively MCP 툴 사용** 시. 개인 레포에선 게이트가 애초에 안 뜸. setup 이 조직 work-root(예: 워크스페이스 경로)를 1건 시드하며, 비면 기본은 "밖에선 침묵"(오설정이 누구도 귀찮게 하지 않음).
- **incognito(`LIVELY_OFF=1`)**: 훅 4종 전부(session-preload·work-flag·stop-writeback-gate·run-custom) no-op — 컨텍스트·리플렉스·게이트·커스텀 훅 전부 off(클린룸). 구 `LIVELY_HOOKS_OFF` 는 back-compat alias.

## E. 자주 묻는 것

| 증상 | 답 |
|---|---|
| 훅이 부담스럽다 / 개인작업 분리 | `LIVELY_OFF=1` 환경변수로 즉시 전체 비활성(클린룸, 재시작 불요). 구 `LIVELY_HOOKS_OFF` 도 동작(alias) |
| 토큰을 잃어버림/유출 의심 | 관리자가 UI '구성원/토큰' 탭에서 해당 토큰 회수(즉시) + 새 토큰 발급 → 전달, 멤버는 새 토큰으로 설치 재실행. (정적 토큰이면 `AUTH_TOKENS_JSON` 항목 교체 + 게이트웨이 재시작.) |
| 팀 컨텍스트가 옛날 것 같다 | 보통 매 세션 자동 갱신이라 그대로. 훅/설정 갱신이 필요하면 설치/업데이트 재실행(`/install` 최신 묶음) |
| 세션 시작 현황이 안 뜬다 | `~/.lively/token`·`~/.lively/context.md` 존재 확인 — 없으면 설치 재실행. 그래도 안 되면 게이트웨이(:8080) 상태 확인 |
| writeback 게이트가 개인 레포에서도 뜬다 | 그 세션에서 lively MCP 툴을 썼거나 cwd 가 등록 work-root 아래라 그렇다 — `LIVELY_OFF=1` 로 끄거나 work-roots 에서 해당 경로 제거 |
| MCP 연결 안 됨 | `claude mcp list` 로 `lively ✔` 확인 → 없으면 설치 재실행 |
