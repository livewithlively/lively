# 프로젝트 마무리(close-out) 루틴

프로젝트(또는 독립 작업 단위)를 끝낼 때, **done 처리 직전~직후 아래를 순서대로** 수행한다. 누락하면 맥락이 비어 다음 사람이 처음부터 재추적해야 한다. (이 루틴 제목은 WIKI 인덱스에 항상 노출되어 마무리 시 소환 트리거 역할 — 본문은 그때 `knowledge_get`.)

1. **프로젝트 본문 보강 (append-only)** — `project_update_v6` 로 description 에 결과·근본원인·해법·검증·반영(커밋/머지) 요약을 덧붙인다. **사용자의 최초 서술(원문)은 절대 지우지 말고 유지**하고, 그 아래에 `--- (마무리 YYYY-MM-DD) ---` 블록으로 덧붙인다. (참고: `append_description` 인자를 쓰면 기존 본문을 다시 쓰지 않고 원문 보존한 채 끝에 이어붙일 수 있다 — 전체 교체가 필요할 때만 `description`. 둘은 동시 사용 불가. #357)
2. **산출지식 마저 기록** — 아직 안 쓴 산출물(근본원인·결정·설계·런북)이 있으면 `knowledge_save` 로 **전문** 기록(요약·포인터 금지) 후 `project_link_knowledge_v6(relation=produced)` 로 연결. 작업에 필요했던 배경지식은 `required` 로도 연결.
3. **태스크 상태** — 끝난 task/subtask 를 `task_set_status_v6(done)`.
4. **프로젝트 상태** — `project_set_status_v6(done)` (완료시각 기록).
5. **후속 과업** — 이번 범위 밖의 남은 후속 작업이 보이면 **먼저 사용자에게 과업화할지 묻는다**(임의 생성 금지). 과업화하기로 하면 **기존 프로젝트의 하위 태스크가 아니라 새 `project_create_v6` 프로젝트**로 만든다 — 후속은 별개의 맥락 단위다. 이때 **MCP 는 `list_id`(소속 리스트/영역) 필수**(`project_list_index_v6` 로 id 조회), 그리고 **선행(이 프로젝트)이 있으면 `follow_up=선행 id`** 로 후속 엣지까지 연결한다(#340 — 프로젝트↔프로젝트 관계가 상세 UI '후속/선행'에 보인다).

6. **워크스페이스 회수** — `workspace_reclaim` 으로 **복구 가능한 것만** 되돌린다. 아래 §6 참조.

진척·커밋은 마무리와 별개로 그 자리에서 `activity_log` 로 얇게 남긴다(상시).

## §6. 워크스페이스 회수

**왜 마무리 루틴에 있나.** 프로젝트마다 워크트리가 생기고 그 안에 의존성·빌드 산출물이 쌓인다(프로젝트 1개당 수백 MB~GB, 그중 대부분이 재설치·재빌드로 복구되는 것들). 아무도 안 치우면 박스 디스크가 차고, **디스크가 차면 DB 가 죽어 로그인을 포함한 모든 기능이 멈춘다**(공간을 비워도 컨테이너 재시작이 필요하다). 그렇다고 **무인 자동 삭제**를 두지는 않는다 — 되돌릴 수 없는 삭제는 **맥락을 아는 주체가 생애주기 경계에서** 해야 안전하다. 그 경계가 여기다.

**호출.**
```
workspace_reclaim(project_id=<id>)                                    # 기본 = dry-run (아무것도 안 지움, 계획만)
workspace_reclaim(project_id=<id>, apply=true)                        # 파생물 회수
workspace_reclaim(project_id=<id>, apply=true, remove_worktree=true)  # 워크트리까지(조건 충족 시)
```

**절차 (반드시 이 순서).**
1. **dry-run 먼저** — 무엇이 `derived`(회수) / `unclassified`(미분류, 안 지움) / `protected`(보호)로 잡혔는지 본다.
2. **사용자에게 보고** — "파생물 X MB 회수 가능. 워크트리는 [제거 가능 / 거부: 사유]" 를 알리고 확인받는다.
3. **apply** — 파생물 회수. 재빌드/재설치로 복구된다.
4. **워크트리 제거는 `remove_worktree=true`** — 단 **푸시 완료 + 미커밋 변경 없음**일 때만 코드가 허용한다. 그 조건이면 나중에 provision 한 번으로 완전히 복구된다.

**코드가 강제하는 안전선(우회 불가).**
- **gitignored 이면서 동시에 알려진 파생물**(node_modules·build·target·dist·.gradle·Pods…)일 때만 지운다. gitignored 라는 이유만으론 안 지운다 — `.env`(시크릿)·`data/`(로컬 데이터)도 전부 gitignored 다.
- allow-list 밖의 gitignored 항목은 `unclassified` 로 **보고만** 하고 손대지 않는다.
- **심링크는 회수하지 않는다** — 크기가 우리 것이 아니고, 지워봐야 링크만 끊어져 남의 의도적 배치를 깨뜨린다.
- **미푸시 커밋 · 미커밋 변경 · upstream 없는 브랜치 → 워크트리 제거 거부**(이유를 문장으로 돌려준다).
- **활성 세션이 그 워크트리에서 돌고 있으면 아무것도 하지 않는다.**

**⚠ 하지 말 것.** 셸에서 `rm -rf node_modules` 같은 걸 직접 치지 마라. 이 도구를 써라 — 위 안전선이 코드로 강제되고 무엇을 지웠는지 기록에 남는다. (모노레포의 중첩 node_modules·보호목록·푸시 검사·세션 검사를 손으로 다시 구현하면 반드시 사고가 난다.)

**박스 전체 현황**은 관리 ▸ 저장소·로그 에서 본다(프로젝트별 회수 가능량 + 수동 회수 버튼, 디스크 경고 임계치, 경보 웹훅).
