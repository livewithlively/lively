# liv-connect-claude — Claude 에 연결된 앱으로 모으기

이 사람이 Claude 에 이미 연결해 둔 앱(슬랙·지메일·노션)으로 일 자료를 모은다. 라이블리 앱 길과 **다른 길**(`ai`)이다 — 라이블리가 그 앱에 직접 연결하지 않고, 이 사람의 Claude 커넥터로 서버의 수집 실행이 읽어 온다. 앱 스킬(`liv-connect-<앱>`)의 «길 고르기»가 `ai` 길을 권했거나 사람이 이 길을 골랐을 때 쓴다.

## 0. 길 상태

`org_connect_status` 의 그 앱 줄에서 `ai` 길의 `state` 를 본다(`ai_app` 이 이 길로 모으는 앱 — 구글은 `gmail`):
- `connected` → 3(목록 훑기)부터.
- `reconnect` → 그 앱에 다시 로그인해야 한다 — 2의 1~2를 «다시 연결»로 안내한다.
- `connect` → 2(Claude 에서 연결)부터. 그 길에 `needs:"claude_login"` 이 있으면 먼저 Claude 로그인이다 — «라이블리 [내 설정 ▸ AI 계정 연결]에서 Claude 로그인을 먼저 해 주세요. 라이블리가 그 로그인으로 Claude 에 연결된 앱을 읽어요.» 로그인한 뒤 1로 확인한다.
- `off` → 이 워크스페이스는 관리자 설정으로 이 길을 쓰지 않는다. 그 사실을 한 줄로 말하고 앱 스킬의 다른 길로 돌아간다.

## 원칙

- **모으는 일은 수집 실행이 한다** — `collect_claude_run`. 이 대화에서 커넥터 도구(`mcp__claude_ai_*`)로 직접 읽어 옮겨 적지 않는다. 그러면 원문 저장·읽은 위치·중복 합치기·볼 수 있는 사람 계산을 전부 건너뛴다.
- **같은 대화를 두 길로 모으지 않는다.** 그 앱의 라이블리 앱 길이 `collecting` 이면 이 길을 쓰지 않는다(`org_connect_status` 의 `routes`).
- **범위는 당신이 판단해 제안하고, 사람은 고르거나 고친다.** 확실하지 않으면 모으는 쪽으로 제안하고 이유를 말한다.

## 1. Claude 에 연결된 앱을 확인한다

- `member_ai_connectors_refresh` 를 부른다(수 초~수십 초). 결과의 `record.scan.ok` 와 `record.connectors`(앱 · 상태)를 본다.
  - 15초 안에 다시 부르면 방금 값이 온다(`skipped:"recent"`) — 잠깐 뒤에 다시 부른다.
  - `skipped:"policy-off"`·`"policy-unknown"` → 이 워크스페이스는 관리자 설정으로 Claude 에 연결한 앱을 쓰지 않는다. 그 사실을 한 줄로 말하고 라이블리 연결(`liv-connect`)로 돌아간다.
  - `scan.ok=false` 면 사유대로 말한다: `not-logged-in`·`not-claude-ai-login` = 서버에서 이 사람의 Claude 로그인이 확인되지 않는다([내 설정 ▸ AI 계정 연결]에서 Claude 로그인이 필요하다) · `timeout`·`no-capacity` = 지금 확인이 안 됐다(조금 뒤 다시) · `unconfirmed-empty` = 있던 앱이 한꺼번에 안 보였다 → 한 번 더 부른다.
- 상태는 `connected`(연결됨) · `needs-auth`(그 앱에 다시 로그인 필요) · `failed`(연결 실패)를 사람 말로 옮긴다.
- 지금 수집 실행으로 모을 수 있는 앱은 슬랙·지메일·노션이다. 그 밖의 앱은 «연결돼 있지만 그 앱에서 자료를 모으는 길은 아직 없어요»라고 사실대로 말한다.

## 2. 빠진 앱 — Claude 에서 연결

빠진 앱이 Claude 커넥터 목록에 있는 앱이면 한 걸음씩 안내한다:
1. «Claude 웹을 열어 주세요: https://claude.ai/customize/connectors — 라이블리에 로그인해 둔 그 Claude 계정이어야 해요.»
2. «[+]를 누르고 ○○를 찾아 [Connect]를 누르세요. ○○ 로그인 화면이 뜨면 로그인하고 허용하세요.»
3. Claude 팀·엔터프라이즈 요금제면 조직 관리자가 먼저 그 앱을 켜야 목록에 보일 수 있다 — 안 보인다고 하면 이 말을 해 준다.
4. 사람이 «했어요»라고 하면 1을 다시 해서 직접 확인한다.

## 3. 무엇이 있는지 목록을 훑는다 — 앱마다

- `collect_claude_run { mode:"listing", app:"slack"|"gmail"|"notion" }` → 받은 `run_id` 로 `collect_claude_run_get { run_id, wait_sec:25 }` 를 끝날 때까지 되풀이한다. `state:"done"` 이고 `ingest.state` 가 `done`(또는 `failed`)이면 끝이다.
  - **한 사람에 한 번에 하나**다. 앱을 차례로 돌린다. 409(이미 도는 실행)면 그 실행이 끝나기를 기다렸다가 다시.
  - 403 = 정책이 막았다 → 라이블리 연결로 돌아간다. 503 = 정책을 못 읽었다 → 조금 뒤 다시.
- 끝나면 `exit`·`ingest` 를 본다. `no-connector`·`connector_load` 실패 = 그 앱 커넥터가 이 실행에 안 실렸다 → 1로 다시 확인. 지메일은 메일함이 **라이블리 계정 이메일과 같은 주소일 때만** 모을 수 있다 — `refused` 가 있으면 그 사실을 말한다.
- `ingest.proof_pending` 이 있으면, 이미 모인 비공개 대화·페이지라 목록만으로는 이 사람에게 열리지 않는다. 주기 수집이 곧 확인 읽기를 돌려 연다 — 그 수만큼 «확인 중이에요. 곧 자동으로 열려요»라고 말한다.
- `collect_units { app }` 으로 찾은 곳(채널 하나·메일함 하나·페이지 묶음 하나)을 본다. `visibility_enforced` 도 본다.

## 4. 무엇을 모을지 정한다

- 단위마다 모을 것 / 뺄 것을 판단한다. 뺄 것의 예: 알림 봇만 오가는 채널, 오래 조용한 채널, 잡담·개인용, 뉴스레터.
- 공개범위는 서버가 종류로 먼저 제안해 둔 값(`visibility`)을 그대로 보여 준다: 공개 채널 = 모두 · 비공개 채널 = 볼 수 있는 사람만 · DM·메일함 = 나만. `visibility_enforced=false` 면 «이 워크스페이스는 자료 공개범위를 쓰지 않아서, 모은 자료가 모두에게 보여요»라고 반드시 말한다.
- 처음에 거슬러 읽는 기간은 기본 최근 14일이다. 더 원하면 단위 `meta.first_days`(1~365)로 늘린다. 길수록 처음 수집이 오래 걸린다고 말한다.
- 앱마다 «찾은 곳 N · 모을 곳 M · 뺄 곳 K»와 뺄 곳의 이름·이유를 보여 주고 «이대로 모을까요?»라고 확인받는다.
- 반영: 단위마다 `collect_unit_update { id, state:"active"|"excluded", visibility?, meta?:{first_days} }`. 공개범위를 넓히는데 이미 모은 자료가 있으면 409 와 건수가 온다 → 몇 건이 누구에게 열리는지 말하고 **사람이 답한 뒤에만** `confirm:true` 로 다시 보낸다.

## 5. 처음 수집

- `collect_claude_run { mode:"collect" }` → `collect_claude_run_get` 으로 끝날 때까지(위와 같이 `ingest.state` 까지). 한 판에 단위 최대 6곳이다. 모을 곳이 더 남았으면 다음 판을 이어 돌린다 — 이 대화에서는 최대 4판까지, 그 뒤는 주기 수집이 이어 간다고 말한다.
- 409 «맡은 단위 없음» = 모으기로 정한 곳이 없거나 라이블리 수집기가 맡았다 → 4로 돌아가 확인한다.
- 끝나면 아래 공통 규칙의 «연결 뒤»대로 보고한다.
