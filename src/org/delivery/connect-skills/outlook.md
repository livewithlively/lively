# liv-connect-outlook — 아웃룩 연결

아웃룩 메일(Microsoft 365 회사 계정·outlook.com 개인 계정)을 라이블리 자료함으로 모은다. 일정은 모으지 않고 AI 도구로만 쓴다.

## 길 고르기

`org_connect_status` 의 `outlook` 줄을 본다. `routes` 는 아웃룩을 연결할 수 있는 길이 우선순위 순서로 들어 있고(`app` 라이블리 앱 하나), `recommended` 가 권하는 길이다. 그 길부터 한다. 배포 방식은 묻지 않는다 — 길의 상태가 이미 그것을 반영한다.
- `blocked_before` 에 길이 있으면 그 사정을 한 줄로 먼저 말한다:
  - 라이블리 앱이 `preparing` → «라이블리가 아웃룩 연결 앱을 준비하고 있어요.»
  - 라이블리 앱이 `ask_admin` 이고 `app_ready=false` → «라이블리 관리자가 먼저 Microsoft 앱을 등록해야 해요.» 관리자에게 보낼 한 줄을 적어 준다: «라이블리 [외부 앱 연결] ▸ 아웃룩에서 ‹앱 등록›을 하면 돼요.» (`app_ready=true` 면 앱은 있고 이 사람이 수집을 켤 수 없는 것이다 — «수집을 켜는 건 관리자가 해요» 라고만 말한다.)
- 길은 아래 «라이블리 앱» 하나다.
- 상태를 더 자세히 볼 때는 `org_outlook_collect` 다(앱 준비 `app_ready` · 내 연결 `me_connected` · 켜짐 `enabled` · 누구 연결로 도는지 `member` · 관리자에게 보낼 링크 `admin_consent_url` · 마지막 실행 `last_run`).

## 라이블리 앱

라이블리 앱 길의 `state` 마다:
- `collecting` → «확인»만 한다.
- `set_scope` → «켜기»부터.
- `connect` → «연결»부터.
- `register` → «앱 등록»부터(이 사람이 등록할 수 있다). 끝나면 «연결»로 이어 간다.
- `ask_admin` → 앱이 아직 없으면 «길 고르기»의 관리자 한 줄로 끝낸다(아웃룩은 다른 길이 없다). 앱이 있는데 `ask_admin` 이면 이 사람은 수집을 켤 수 없다 — 관리자에게 «아웃룩 수집 켜기»를 부탁하게 한다.
- `preparing` → «라이블리가 아웃룩 연결을 준비하고 있어요»라고만 말하고 끝낸다.

### 연결 — 회사 계정은 관리자 허용이 먼저일 수 있다

1. `org_outlook_connect {}` 를 부른다 → `authorization_url`·`admin_consent_url`.
2. 계정 종류를 묻는다: 회사·학교 계정(Microsoft 365)인지, 개인 outlook.com 계정인지.
   - **회사 계정**이면 연결 전에 먼저 말한다: «회사에 따라 Microsoft 365 관리자가 먼저 ‹조직 전체 허용›을 해 줘야 연결돼요. 막히면 이 링크를 회사 Microsoft 365 관리자(전역 관리자나 클라우드 앱 관리자)에게 보내 주세요.» 그리고 `admin_consent_url` 을 준다. 관리자는 라이블리 계정이 없어도 된다 — 링크를 열고 관리자 계정으로 로그인한 뒤 [수락]만 누르면 된다.
   - 개인 계정이면 관리자 허용은 필요 없다.
3. `authorization_url` 을 주고 말한다: «이 링크를 열고 계정을 고른 뒤 [허용]을 눌러 주세요.» 링크는 10분 동안만 쓸 수 있다.
   - «관리자 승인 필요»가 뜨거나 허용 화면에서 막히면 2의 관리자 링크를 보내게 하고, 관리자가 [수락]한 뒤 1부터 **다시** 연결한다.
4. 사람이 «했어요»라고 하면 `org_outlook_collect` 로 `me_connected=true` 를 확인한다. 첫 연결 때 AI 가 메일·일정을 읽는 도구도 함께 준비된다.
- 연결만으로는 수집이 켜지지 않는다 — 아래 «켜기»에서 켠다.

### 켜기

- 아웃룩은 고를 범위가 없다 — 연결한 메일함 전체를 모은다(지운 편지함·정크·임시 보관함·보낼 편지함은 빼고). 언제부터 읽을지만 정한다(비우면 메일함 전체).
- ⚠ 모은 메일은 이 워크스페이스 구성원 **모두에게 보인다**(공개범위 규칙을 따로 정하지 않았다면). 개인 메일이 섞이므로 반드시 먼저 말하고 동의를 받는다.
- 켜기: `org_outlook_collect_set { enabled:true, scope:{ backfill_since:"YYYY-MM-DD" } }` — 날짜는 꼭 `scope` 안에 넣는다(바깥에 두면 무시된다). 날짜를 정하지 않았으면 `scope` 를 빼고 보낸다.
  - ⚠ 수집기는 워크스페이스에 하나이고, 켤 때마다 **부른 사람의 메일함**으로 바뀐다. `member` 가 이 사람이 아니면 먼저 말한다: «지금은 ○○님 메일함을 모으고 있어요. 켜면 이제부터 당신 메일함으로 바뀌어요.» 동의를 받은 뒤에만 부른다.

### 확인

- 켜면 첫 수집이 바로 시작된다(처음엔 메일함 전체를 읽어 오래 걸릴 수 있다). 1~2분 뒤 `org_outlook_collect` 의 `last_run` 을 본다. 들어온 자료: `source_list { system:"outlook", limit:5 }`.
- 메일 정리 규칙(증류기)은 자동으로 생기지 않는다 — 공통 규칙 «연결 뒤» 3을 꼭 한다.

### 함정

- 라이블리 계정과 **같은 이메일의 메일함**을 연결하게 한다 — 메일함 이름이 라이블리 계정 이메일로 붙는다.
- 연결한 사람이 연결을 끊거나 떠나면 수집이 멈춘다.
