# liv-connect-notion — 노션 연결

노션 문서를 라이블리 지식으로 모은다.

## 길 고르기

`org_connect_status` 의 `notion` 줄을 본다. `routes` 는 노션을 연결할 수 있는 길이 우선순위 순서로 들어 있고(`app` 라이블리 앱 → `ai` Claude 커넥터), `recommended` 가 권하는 길이다. 그 길부터 한다. 배포 방식은 묻지 않는다 — 길의 상태가 이미 그것을 반영한다.
- `blocked_before` 에 길이 있으면 그 사정을 한 줄로 먼저 말한다:
  - 라이블리 앱이 `preparing` → «라이블리가 노션 연결 앱을 준비하고 있어요.» 그동안은 다른 길로 모을 수 있어요.
  - 라이블리 앱이 `ask_admin` 이고 `app_ready=false` → «라이블리 관리자가 먼저 노션 통합을 등록해야 해요.» 관리자에게 보낼 한 줄을 적어 준다: «라이블리 [외부 앱 연결] ▸ 노션에서 ‹앱 등록›을 하면 돼요.» (`app_ready=true` 면 앱은 있고 이 사람이 수집을 켤 수 없는 것이다 — «수집을 켜는 건 관리자가 해요» 라고만 말한다.)
  - Claude 커넥터가 `off` → `off_reason=blocked` 면 이 워크스페이스는 구성원 Claude 커넥터를 쓰지 않게 해 두었다. 그 길은 말하지 않는다(`unknown` 이면 지금 확인을 못 한 것이다 — 관리자가 껐다고 말하지 않는다).
- 길마다 절: `app` → 아래 «라이블리 앱» · `ai` → `liv-connect-claude` 스킬로 넘긴다(사람이 Claude 에 연결해 둔 노션으로 모은다).
- 권하는 길을 끝낸 뒤 더 나은 길이 남아 있으면 **한 번만** 권한다 — Claude 커넥터로 모으기로 했는데 라이블리 앱이 `connect` 면: «고른 페이지를 빠짐없이 모으려면 라이블리 앱으로 한 번 허용하면 돼요.» 사람이 원하지 않으면 다시 꺼내지 않는다.
- 상태를 더 자세히 볼 때는 `org_notion_collect` 다(준비 `ready` · 연결된 노션 워크스페이스 `workspaces[]` — 각 줄의 `enabled`·모은 페이지 수 `pages`·첫 수집이 끝났는지 `first_sync_done`).

## 라이블리 앱

라이블리 앱 길의 `state` 마다:
- `collecting` → «확인»만 하고, 페이지를 더 고를지 묻는다.
- `set_scope` — 연결은 돼 있는데 수집이 꺼져 있다. 사람에게 말한 뒤 `org_notion_collect_set { enabled:true }` 로 켜고 «확인»으로 간다.
- `connect` → «연결»부터.
- `register` → «앱 등록»부터(이 사람이 등록할 수 있다). 끝나면 «연결»로 이어 간다.
- `ask_admin` → 앱이 아직 없으면 «길 고르기»의 관리자 한 줄. 앱이 있는데 `ask_admin` 이면 이 사람은 수집을 켤 수 없다 — 관리자에게 «노션 수집 켜기»를 부탁하게 한다.
- `preparing` → 사람이 할 일은 없다. 다른 길로 간다.

### 연결 — 고르는 페이지가 곧 모을 범위

1. `org_notion_collect_connect {}` 를 부른다 → `authorization_url`. 그 링크를 주고 말한다: «이 링크를 열고 노션 워크스페이스를 고른 뒤, 라이블리가 읽을 페이지를 골라 [액세스 허용]을 눌러 주세요.» 링크는 10분 동안만 쓸 수 있다.
2. 페이지 고르는 법을 함께 말한다:
   - 노션 화면에는 «전체 선택»이 없다. **사이드바 맨 위 단계의 페이지를 고르면 그 아래 페이지가 함께 들어온다.** 빠뜨리기 쉬우니 맨 위 단계 페이지를 하나씩 확인하게 한다.
   - 모두가 봐도 되는 페이지만 고르게 한다. 고르지 않은 페이지는 읽지 않는다.
3. 사람이 «했어요»라고 하면 `org_notion_collect` 의 `workspaces[]` 에 그 워크스페이스가 생겼는지 확인한다. 동의가 끝나면 **수집이 저절로 켜진다** — 따로 켤 필요가 없다.
- 이 연결은 사람이 아니라 **노션 워크스페이스 단위**다. 누가 한 번 연결하면 그 워크스페이스는 연결된 것이다.
- 개인 AI 가 노션을 직접 쓰는 연결(`me_oauth_connect { server:"notion" }`)은 이것과 별개다 — 그 연결로는 자료를 모으지 않는다.

### 범위 바꾸기

- **페이지를 더 고르려면** «연결»의 1을 다시 하고 같은 워크스페이스에서 페이지를 더 고른다(이미 고른 것은 그대로).
- **다른 노션 워크스페이스**를 고르면 그 워크스페이스가 하나 더 연결된다.
- 특정 페이지를 빼려면 `org_collectors` 에서 그 워크스페이스의 노션 수집기(key `notion-…`)를 찾아 `org_collector_upsert { id, config:{ exclude_pages:"<페이지 id 또는 링크, 쉼표 구분>" } }`. 수집기의 `instance` 설정은 바꾸지 않는다(바꾸면 처음부터 다시 모은다).
- 끄기: `org_notion_collect_set { enabled:false, workspace_id? }` — 지우는 게 아니라 멈추는 것이다.

### 확인

- 첫 수집은 동의 직후 시작된다. `org_notion_collect` 의 `first_sync_done` 이 true 가 된 뒤에 `pages`(모은 페이지 수)를 말한다 — 그 전의 0은 «0개»가 아니라 «아직 세는 중»이다.
- 노션 문서는 자료함을 거치지 않고 **지식으로 바로** 들어온다(원문 그대로, 외부 미러). 그래서 노션만을 위한 정리 규칙(증류기)은 필요 없다. 들어온 문서: `knowledge_search { q:"<페이지 제목>" }`.

### 함정

- 노션 연결은 시간이 지나 만료될 수 있다(라이블리가 자동으로 갱신하지 않는다). 수집이 «권한»·«토큰» 오류로 멈추면 «연결»의 1을 다시 하면 된다.
